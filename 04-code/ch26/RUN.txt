Things that went wrong or changed on the way, and are told in the chapter where they matter:
  - The first launch of the 400-step grid did not save final tables; it was stopped after about two minutes and relaunched with
    torch.save added.  Chapter 24's repeat, started at the same time, was left running.
  - A second grid (jobs_seeds2.txt: seeds 21 and 42, lr 1.4e-3 on five seeds, start-only and order-only seeds 21 and 42) was added
    while the first was running, by appending to run_seeds.sh; the running shell read the appended lines and ran it after the first grid.
    train_seeds.py gained an LR switch at the same time (default unchanged, so runs already queued were not affected).
  - fp_order.py was run twice (its printout of Part C was changed).  Part D's counts of gradient numbers differing from one thread were
    2,456,475 / 2,458,596 / 2,458,572 (2 / 4 / 8 threads) the first time and 2,456,459 / 2,458,591 / 2,458,605 the second: multi-threaded
    gradients are not repeatable on this machine.  The chapter quotes the second run and reports the first.
  - analyse.py first globbed seeds_*.json, which also matched seeds_demo.json; changed to seeds_i*.json.
  - analyse.py Part 5 first scored heldout_sets()[1], which is the 16-window Carroll held-out sample, not Looking-Glass; changed to the
    first 64 non-overlapping Looking-Glass windows (8,192 predictions), and the lowest two frequency bands merged (only 3 tokens below 10).
  - repeat_hosted.py: the API rejected temperature 0 for claude-haiku-5-5 ("`temperature` is deprecated for this model."); default sampling
    was used.  Of 20 replies to the cloze prompt, 16 did not give a letter within 40 tokens; kept as measured.
  - Thread-count runs shared the machine with up to five other jobs, so their wall times (157 s and 206 s) are not speed measurements.
  - Spreads added as squares predicted 0.18 for runs changing both seeds; five such runs spread by 0.094.  Kept and discussed (26.7).

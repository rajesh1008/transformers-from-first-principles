What went wrong (tick 23), told as it happened:
  - First launch of step_cost.py used `python` (not installed); re-run with python3.
  - step_cost.py failed: ../ch22/_pool.py imports tok() from _common, which ch31/_common.py lacked (the same slip
    Chapter 30 made).  Added tok() and re-ran.
  - The simulator's static scheme was written with padded prefill and per-request return, the real server with
    per-request prefill and batch return; the two disagree (simulated TTFT 14.17 s vs real 6.37 s).  Kept both and
    said so in 31.4 rather than tuning the simulator to agree.
  - The fitted decode-step model misses by up to 27%; the third term mixes cache reading with the cost of torch.cat
    copying each cache on every append (not separated).
  - In the paged-memory experiment (experiments.py Part D), paging did not raise throughput on this CPU (51.4 vs 52.4
    tokens/s, 31 pre-emptions), because each resident conversation's cache slows every step; reported as measured.
  - Chunks of 32 made the simulated server unstable (throughput 31.7 tokens/s below the arrival rate at 1 req/s).
  - The tell-scan flagged a question-then-answer opener, "percent" in "single-digit-percent", and a paper title
    ending in "?" in a footnote; all three rewritten.
  - First drafts of the prose overstated three things that the outputs did not show (that the first static batch was
    followed by ten queued requests; that a 10-token reply shared a batch with the 123-token one; batching's cost
    factor 5.7, which is the B16 figure); corrected against outputs before the build.

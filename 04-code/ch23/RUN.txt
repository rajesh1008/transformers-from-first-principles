Things that went wrong on the way, and are told in the chapter:
  - THE FIRST LADDER READ THE BOOKS ONE AFTER ANOTHER.  The first version wrote each pool book as one document, giving four shards (the
    largest book is bigger than a 65,536-token shard).  ShardStream shuffles the shard order and a 256-window buffer, so each run read the
    books nearly in sequence: the last sixth of a one-pass run read 82% Sylvie and Bruno Concluded (order 1865), 85% A Tangled Tale (order 11).
    Order spreads grew with size (0.37 for s6 at lr 1e-3; up to 0.42 at 3e-3) and order 11 ended worst for every large size, its held-out loss
    rising over the last 100 steps.  All 74 runs were redone with 24 shards of shuffled 4,096-token pieces (largest single-book share in a batch
    0.50, against 0.66 to 1.00 before).  The first ladder's outputs are kept in outputs/v1_four_shards/ and its analyse.txt is quoted once.
  - SAME CONFIGURATION, DIFFERENT LOSS.  The first ladder's five order-1865 runs at lr 1e-3 were run twice (the second time to record the
    sentence loss) and none repeated exactly: held-out differences 0.0007 to 0.043.  repro_probe.py shows that the BF16 products of
    MixedTiny differ between two runs from the second step, by about 6e-5 in the batch loss, while 32-bit products repeat bit for bit at one
    thread.  The cause inside the BF16 matrix product was not isolated.  Chapter 22's mixed-BF16 runs (tick 15) are affected the same way;
    STATE.md NEXT records it.  repro.sh measures the size of the effect on the second ladder.
  - The attention count in analyse.py Part 9 was first written at half its value (forward and backward counted as 6/2 instead of 3 x forward);
    fixed before any number was used.
  - fit_floor's E search runs from 0 to just below the smallest loss; with the lr 3e-3 sweep of the first ladder it ended at 0 or at the top for
    some fits, which the at_edge / at_zero flags report.

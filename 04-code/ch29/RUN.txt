What went wrong:
- tiny_bpc.py found that Tiny scored in 1,024-token windows is much worse than in 129-token windows (2.439 against 1.981 bits
  per character): positions 128 onwards were never trained (Chapter 24's windows were 129 tokens).  Every scoreboard since
  Chapter 14 printed "context length 1,024"; the chapter corrects this to "trained context 128".
- The first comparison of bits per character put GPT-2 (1,024-token windows) against Tiny (129-token windows); unequal context.
  gpt2_short.py was added to match context (110 GPT-2 tokens), which cut the gap from 0.42 to 0.105 bits per character.
- smollm2.py first used 127-token windows for "matched context"; at 0.279 tokens per character that is about 455 characters,
  not Tiny's ~352.  Changed to 98 tokens and rerun (1.3006; the 127-token run gave 1.2524).
- precision.py ran every operation in the low format, including layer norm; FP16 came out far worse than BF16 (7.2 against
  0.75 nats).  precision_ln.py traced it to squared deviations up to 9.2 million overflowing FP16's 65,504 inside the layer
  norm; with norms in 32-bit FP16's error falls to 0.106.
- load_gpt2.py's first listing printed three h.0 tables twice (a sorted()[:3] slice that overlapped); fixed, rerun.
